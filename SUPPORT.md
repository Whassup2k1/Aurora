## 🧭 Where Should I Go?

### 🐛 I Found a Bug

If Aurora is not behaving as expected, please report the problem through
GitHub Issues.

When reporting a bug, include as much useful information as possible:

- Aurora version
- Operating system and version
- Browser or Aurora client
- Hardware architecture when relevant
- What you were trying to do
- What you expected to happen
- What actually happened
- Steps that reproduce the problem
- Relevant logs
- Screenshots when useful

A clear and reproducible report makes problems much easier to investigate.

---

### 💡 I Have a Feature Suggestion

Feature ideas and improvements are welcome.

Aurora is built around a consistent product vision, so not every suggestion
will necessarily become part of the platform.

Suggestions are evaluated according to:

- Usefulness
- How commonly the need is shared
- Consistency with the Aurora experience
- Complexity and long-term maintenance
- Impact on existing users

> **Listen to everyone. Build for the majority. Protect the vision.**

## 🌍 Translation & Localization

Aurora is multilingual by design.

Localization feedback is especially useful during Early Access.

Please report problems such as:

- Missing translations
- Incorrect translations
- Unnatural wording
- Text that does not fit correctly
- Incorrect locale formatting
- Sections that remain untranslated

When reporting a translation problem, include the language and the part of
Aurora where the problem appears.

## 🔐 Security Issues

**Do not report security vulnerabilities through a public GitHub Issue or
Discussion.**

If you believe you have discovered a security vulnerability, follow the
responsible disclosure process described in:

**[→ Aurora Security Policy](SECURITY.md)**

Never publicly post:

- Passwords
- API keys
- Access tokens
- Private keys
- Authentication cookies
- Private credentials
- Sensitive server information

---

## 🔒 Privacy

Aurora follows a local-first philosophy.

Your personal media is intended to remain on infrastructure you control.

Some optional features may communicate with external services when those
integrations are enabled.

Detailed privacy documentation will be available before wider public
distribution.

---

## 📝 Before Reporting a Problem

Before opening a new report:

1. Make sure you are using a currently supported Aurora build.
2. Check whether the problem has already been reported.
3. Try to reproduce the issue.
4. Collect the relevant error message or logs.
5. Remove credentials and personal information before sharing anything.

Please avoid posting enormous logs when only a small section is relevant.

---

## 🖥 Useful System Information

Depending on the problem, the following information may help:

- Aurora version
- Operating system
- Operating system version
- CPU architecture
- Browser
- Aurora client
- Server hardware
- Installation method
- Relevant media format
- Relevant Aurora logs

You do not need to publish your complete hardware configuration for every
problem.

Only include information that is relevant to the issue.

---

## 🚫 What Should Not Be Posted Publicly?

Before posting screenshots, logs or configuration information, remove:

- Passwords
- Tokens
- API keys
- Private keys
- Authentication information
- Personal information
- Private URLs when sensitive
- Information that could unnecessarily expose your network

If you are unsure whether something is sensitive, remove it before posting.

## 🧪 Early Access Support

During Early Access, Aurora is testing software.

Some problems may be related to:

- Installation
- Updates
- Hardware compatibility
- Operating system differences
- Browser differences
- Media formats
- Network environments
- Large libraries
- Localization
- Features still under development

Reports from different environments are extremely valuable during this phase.

The purpose of Early Access is to find these problems before Aurora reaches a
wider audience.
